# Ассеты: что вы предоставляете

[English](assets.md) · **Русский**

`make assets SRC=<каталог>` превращает ваше **уже извлечённое** дерево XDJ-RX3
**v1.20** в четыре входа для сборки. Скрипт ничего не скачивает, не расшифровывает
и не добывает (см. [NOTICE.ru.md](../../NOTICE.ru.md)).

## На входе

`<каталог>` — тот, в котором лежат:

```
<каталог>/
├── gui/
│   ├── fontdata/
│   └── imagedata/
└── images/
    ├── rootfs.cramfs
    ├── gui.tar.gz
    ├── pdj.tar.gz        (внутри pdj/rbp — штатный плеер)
    └── release.txt       (1.20)
```

Файл обновления прошивки производитель публикует на странице поддержки XDJ-RX3.
Как из него получить это дерево — вне проекта и на вашей ответственности.

## На выходе (`extracted/`, git его игнорирует)

```
extracted/
├── XDJRX3/gui/       копия gui/ из дерева
├── XDJRX3-gui/       распакованный images/gui.tar.gz (pset/, system/)
├── XDJRX3-rootfs/    распакованный images/rootfs.cramfs (soft-float userland)
└── rbp-audio         pdj/rbp + патчи совместимости (tools/patch-rbp)
```

Проверки по пути: md5 штатного `rbp` должен быть
`4f2efcfc0c9e3f539289f863acfddcc6` (v1.20), md5 результата —
`3dda2d4e10187a75bfc16a7b4f16f192`. Другая версия прошивки не подойдёт: патчи
привязаны к адресам v1.20. Подробнее — [docs/04-firmware-assets.md](../04-firmware-assets.md),
[tools/patch-rbp/PATCHES.md](../../tools/patch-rbp/PATCHES.md).

rootfs распаковывается под root внутри контейнера сборки (в нём есть
device-ноды), потом файлы возвращаются вашему пользователю. На рабочей машине
из него ничего не запускается: шимы только линкуются с его библиотеками.
